# 技术选型分析

## 1. 数字人方案对比

### 1.1 SadTalker

**原理**：基于3DMM（3D Morphable Model）的人脸重建，通过音频驱动人脸动作

**优点**：
- 脸部动作自然（眨眼、头部微动、表情变化）
- 开源成熟，社区活跃
- 支持多种人脸驱动方式

**缺点**：
- 口型同步精度一般
- 对正脸图片效果好，侧脸效果差

**适用场景**：需要自然表情的数字人

### 1.2 MuseTalk

**原理**：基于音频的嘴型区域 inpainting，直接修改嘴巴区域

**优点**：
- 口型同步精度高
- 生成速度快
- 支持视频输入

**缺点**：
- 只驱动嘴巴，脸部其他部分不动
- 看起来比较假

**适用场景**：对口型精度要求高的场景

### 1.3 Wav2Lip

**原理**：基于GAN的唇形同步，生成与音频匹配的嘴型

**优点**：
- 口型同步好
- 支持任意人脸图片/视频

**缺点**：
- 生成质量一般
- 嘴巴区域可能模糊

**适用场景**：快速唇形同步

### 1.4 最终选择：SadTalker + MuseTalk组合

**理由**：
1. SadTalker提供自然的脸部表情
2. MuseTalk优化口型同步
3. 组合效果最佳

## 2. TTS方案对比

### 2.1 Edge-TTS

**优点**：
- 免费
- 音质高
- 支持多种语言和声音
- 无需GPU

**缺点**：
- 需要网络连接
- 语调可能不够自然

### 2.2 GPT-SoVITS

**优点**：
- 支持声音克隆
- 语调更自然

**缺点**：
- 需要GPU
- 需要训练数据
- 部署复杂

### 2.3 最终选择：Edge-TTS

**理由**：
1. 免费且质量高
2. 无需额外GPU资源
3. 部署简单

## 3. RAG方案对比

### 3.1 RAGFlow

**优点**：
- 开箱即用
- 支持多种文档格式

**缺点**：
- 定制化程度低
- 不适合金融领域特化

### 3.2 自研RAG

**优点**：
- 完全可控
- 可针对金融领域优化
- 支持自定义检索策略

**缺点**：
- 开发成本高
- 需要维护

### 3.3 最终选择：自研RAG

**理由**：
1. 金融领域需要特化
2. 已有成熟代码（工单六）
3. 支持多种检索策略

## 4. 部署方案对比

### 4.1 本地部署

**优点**：
- 无网络延迟
- 数据安全

**缺点**：
- GPU资源有限
- 需要高性能硬件

### 4.2 AutoDL云端

**优点**：
- GPU算力充足
- 按需付费
- 环境可复制

**缺点**：
- 需要网络连接
- 有使用成本

### 4.3 最终选择：混合部署

**理由**：
1. RAG系统本地部署（数据安全）
2. 数字人系统AutoDL部署（GPU算力）
3. ngrok内网穿透连接

## 5. 内网穿透方案对比

### 5.1 ngrok

**优点**：
- 简单易用
- 免费版够用

**缺点**：
- 免费版有限制
- 需要注册

### 5.2 frp

**优点**：
- 完全自控
- 无限制

**缺点**：
- 需要公网IP
- 配置复杂

### 5.3 最终选择：ngrok

**理由**：
1. 简单快速
2. 免费版满足需求
3. 无需公网IP
