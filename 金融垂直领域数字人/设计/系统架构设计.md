# 系统架构设计

## 1. 整体架构

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   用户输入   │ →  │  RAG检索    │ →  │  LLM生成    │ →  │  TTS合成    │ →  │  数字人生成  │
│  （文字）    │    │（本地8006）  │    │（DeepSeek）  │    │（Edge-TTS）  │    │（SadTalker+ │
│             │    │             │    │             │    │             │    │  MuseTalk）  │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
```

## 2. 模块划分

### 2.1 RAG检索模块

**职责**：基于用户问题检索金融知识库

**技术栈**：
- FastAPI：API服务
- Milvus：向量数据库
- BGE-M3：Embedding模型（1024维）
- bge-reranker-base：重排序模型
- DeepSeek-Chat：LLM生成回答

**部署位置**：本地Windows

**对外接口**：
```
POST /api/query
{
    "question": "问题内容",
    "strategy": "hybrid"  // hybrid/vector/bm25
}
```

### 2.2 TTS语音合成模块

**职责**：将文本回答转为语音

**技术栈**：Edge-TTS（微软语音合成）

**支持语音**：
- 男声：zh-CN-YunyangNeural
- 女声：zh-CN-XiaoxiaoNeural

**输出格式**：WAV音频文件

### 2.3 数字人生成模块

**职责**：驱动数字人生成说话视频

**技术方案**：SadTalker + MuseTalk组合

**流程**：
1. SadTalker：生成自然脸部表情（眨眼、头部微动）
2. MuseTalk：优化口型同步

**输入**：源图片 + 音频文件
**输出**：MP4视频文件

### 2.4 WebUI模块

**职责**：提供用户交互界面

**技术栈**：Gradio

**功能**：
- 输入框：输入金融问题
- 对话框：显示问答历史
- 视频播放器：播放数字人视频
- 形象预览：显示数字人图片

## 3. 数据流

```
用户输入问题
    ↓
RAG API调用（ngrok内网穿透）
    ↓
返回金融知识回答
    ↓
文本清理（去除Markdown符号）
    ↓
TTS语音合成
    ↓
SadTalker生成基础视频
    ↓
MuseTalk优化口型
    ↓
返回最终视频
    ↓
WebUI展示
```

## 5. 技术选型理由

| 模块 | 选择 | 理由 |
|------|------|------|
| RAG | 自研 | 定制化程度高，支持金融领域特化 |
| TTS | Edge-TTS | 免费、质量高、支持中文 |
| 数字人 | SadTalker+MuseTalk | 组合方案效果最好 |
| 部署 | AutoDL | GPU算力充足，按需付费 |
| 内网穿透 | ngrok | 简单易用，免费版够用 |
