# 工单十三 RAG 性能优化报告

## 1. 验收目标

- 主验收接口：`POST /api/query/retrieve`
- 验收口径：`query -> 检索结果返回`
- 硬性目标：`p95 <= 3000ms`

## 2. 当前环境

- 项目目录：`E:\桌面\项目文件\RAG工单项目\工单十三`
- 后端地址：`http://127.0.0.1:8013`
- Milvus collection：`rag_workorder13`
- Embedding：`BGE-M3`
- Reranker：`bge-reranker-base`
- 当前运行形态：`GPU`
  - `torch==2.5.1+cu121`
  - `transformers==4.51.3`
  - `tokenizers==0.21.4`
  - `huggingface-hub==0.36.2`
  - `safetensors==0.7.0`

## 3. 主要优化动作

1. 新增 `POST /api/query/retrieve`，将检索 SLA 从完整问答链路中独立出来。
2. 在 `/api/query`、`/api/query/stream`、`/api/query/retrieve`、`/api/evaluate` 中统一补齐性能字段：
   - `trace_id`
   - `timings`
   - `retrieval_time_ms`
   - `total_time_ms`
   - `cache_hit`
3. 建立统一阶段埋点：
   - `cache_lookup`
   - `history_load`
   - `embedding`
   - `vector_search`
   - `bm25_search`
   - `merge`
   - `rerank`
   - `context_build`
   - `llm_ttft`
   - `llm_total`
   - `total`
4. 修复 Milvus 与当前 `pymilvus 2.3.4` 的兼容问题。
5. Redis 改为读取密码配置，接通当前容器环境。
6. CPU 路径下收紧 rerank 候选池，先实现首轮达标。
7. 识别并修复 GPU 切换过程中的依赖兼容问题：
   - 沿用 `torch 2.5.1+cu121`
   - 将 Hugging Face 相关依赖回退到与旧 GPU 组合兼容的版本
8. 修复组件初始化并发问题，避免启动预加载和首个健康检查同时触发重复模型初始化。

## 4. 瓶颈定位结论

首轮未启用 GPU 时，慢问题主要落在 CPU rerank：

| 指标 | 数值 |
|------|------|
| Avg | `1226.8ms` |
| P50 | `507ms` |
| P95 | `3518ms` |
| P99 | `4103ms` |
| Under 3s Rate | `0.75` |

进一步拆解后确认：

- `embedding` 约 `150ms - 180ms`
- `vector_search` 约 `220ms - 360ms`
- `rerank` 约 `2500ms - 3100ms`

结论：

- 首轮主瓶颈不在 Milvus
- 首轮主瓶颈不在 embedding
- 首轮真正拉高尾延迟的是 CPU 环境下的 rerank 阶段
