# 用户手册 - RAG 智能问答系统（工单十二）

## 快速开始

### 启动系统
1. 确保 Milvus 已启动（Docker 容器 `milvus-standalone`）
2. 双击 `start.bat`，自动启动后端和前端（WSL环境下会调用 `start_wsl.sh`）
3. 等待模型加载完成（约 30-60 秒）
4. 打开浏览器访问 http://localhost:5173

### 访问地址
| 服务 | 地址 |
|------|------|
| 前端页面 | http://localhost:5173 |
| 后端 API | http://localhost:8006 |
| API 文档 | http://localhost:8006/docs |
| 健康检查 | http://localhost:8006/api/health |

## 功能说明

### 问答
在输入框输入问题，系统会从已加载的文档中检索相关信息并生成回答。

**支持的问题类型**：
- 事实性问题："公司的注册资本是多少？"
- 列举性问题："募集资金拟投资哪些项目？"
- 比较性问题："文档一和文档二的区别在哪儿？"
- 简单问题："公司老板是谁"

**特殊功能**：
- 问候语直接回复（不检索文档）
- 回答中标注信息来源文档
- 支持中英文双语

### 多轮对话
系统支持在同一对话中连续提问，AI 能记住之前的聊天内容。

**使用方式**：
- 直接在同一个对话中连续提问即可，无需额外操作
- AI 会自动记住你之前说过的话

**支持的场景**：
- **追问**：先问"武汉兴图新科的法定代表人是谁？"，再问"那武汉力源信息呢？"，AI 能理解你在问另一家公司的法定代表人
- **个人信息**：先说"我叫李达"，再问"我是谁？"，AI 会回答"你是李达"
- **上下文补充**：先问某个公司的信息，再问"它的注册资本呢？"，AI 知道"它"指的是哪家公司

**注意事项**：
- 对话历史保留最近 10 轮，超过的会被自动清理
- 历史记录 1 小时后自动过期
- 删除对话会同时清除历史记录

### 文档管理
### RAG vs LightRAG 对比

系统支持传统RAG和LightRAG两种检索方式的实时对比。

**使用方式**：
- 在输入框输入问题后，点击输入框右侧的 **"对比"** 按钮
- 系统同时调用传统RAG和LightRAG进行检索
- 弹出对比弹窗，左边展示传统RAG结果（直接展示），右边展示LightRAG结果（流式输出）
- 底部显示两者的耗时对比

**融合回答**：
- 点击 **"融合回答"** 按钮，系统会将两路检索结果交给LLM融合生成最终回答
- 融合回答取两者精华，去除重复，优先使用更准确的信息
- 融合结果以流式方式输出，体验更流畅

**适用场景**：
- 需要验证回答准确性时，对比两种检索方式的结果
- 复杂问题需要综合两路信息时，使用融合回答
- 评估哪种检索方式更适合当前问题

**注意事项**：
- LightRAG首次查询可能较慢（图谱冷启动），后续查询约1-2秒
- 融合回答耗时较长（需同时调用两路检索+LLM融合），约5-8秒
- 对比结果中的来源标注可帮助判断哪个回答更可靠

### 文档管理
- 点击上传按钮上传 PDF 文件
- 系统自动解析 PDF（MinerU + OCR）
- 解析完成后自动建立索引
- 支持多份文档共存

### 对话管理
- 左侧栏显示历史对话列表
- 支持创建、切换、删除对话
- 对话记录保存在 SQLite 数据库

## 常见问题

### Q: 启动报端口占用怎么办？
A: `start.bat` 会自动清理占用端口的进程。如果仍然失败，手动执行：
```bash
taskkill /F /IM python.exe
```

### Q: 回答不准确怎么办？
A: 可能原因：
1. 文档未正确解析 — 检查 `data/` 目录下是否有 `_refined.md` 文件
2. 问题太模糊 — 尝试更具体的问题
3. 信息不在文档中 — 系统会坦诚告知"未找到"

### Q: 响应时间太长怎么办？
A: 响应时间主要取决于 DeepSeek API 负载：
- 问候语：< 0.1 秒
- 简单查询：2-3 秒
- 复杂查询：3-6 秒

如果持续很慢，检查网络连接或 DeepSeek API 状态。

### Q: 如何添加新文档？
A: 在前端页面点击上传按钮，选择 PDF 文件即可。新文档会追加到现有索引中，不会清除旧数据。

### Q: 多轮对话不生效怎么办？
A: 检查以下几点：
1. Redis 是否已启动（`redis-cli ping` 应返回 PONG）
2. 是否在同一个对话中连续提问（不同对话的上下文是独立的）
3. 重启后端后再试

### Q: RAG vs LightRAG对比弹窗加载慢怎么办？
A: 首次对比可能需要等待LightRAG图谱冷启动（约5-10秒）。如果持续很慢：
1. 检查LightRAG服务是否正常启动
2. 检查Neo4j/NetworkX图谱数据是否已构建
3. 尝试单独使用LightRAG查询，确认基本功能正常

### Q: 融合回答和单独RAG/LightRAG回答有什么区别？
A: 融合回答会综合两路检索结果，由LLM生成更全面、更准确的最终回答。适合需要高准确率的场景，但耗时较长（5-8秒）。

### Q: 如何重新构建索引？
A: 删除 `storage/chunks_cache.pkl` 和 Milvus 中的数据，重启服务即可重新构建。
