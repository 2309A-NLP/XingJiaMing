## 问题列表

### 问题 1：Windows 路径在 Docker 容器中无效

**问题描述**：
- `.env` 文件中的模型路径使用 Windows 格式（如 `E:\AI_models\BGE-M3`）
- Docker 容器中无法识别 Windows 路径

**问题原因**：
- 原项目在 Windows 环境开发，路径格式为 Windows 风格
- Docker 容器使用 Linux 系统，需要 Linux 路径格式

**解决方案**：
1. 在 `.env` 中使用容器内路径：`/models/BGE-M3`
2. 在 `docker-compose.yml` 中挂载模型卷：
   ```yaml
   volumes:
     - ai_models:/models
   ```
3. 创建 Docker 卷并复制模型文件

**预防措施**：
- 使用环境变量配置路径，避免硬编码
- 在 `.env.example` 中提供示例路径

### 问题 2：run.py 包含 Windows 特定代码

**问题描述**：
- `run.py` 使用 `tasklist` 和 `taskkill` 命令释放端口
- 这些命令在 Linux/Docker 中不存在

**问题原因**：
- 原项目为 Windows 环境设计
- `_free_port()` 函数使用 Windows 特定命令

**解决方案**：
1. 创建 `run_docker.py`，去除 Windows 特定代码
2. Docker 容器中不需要手动释放端口

**预防措施**：
- 使用跨平台的端口检测方法
- 在 Docker 环境中依赖容器重启策略

---

### 问题 3：requirements.txt 缺少依赖

**问题描述**：
- 代码中导入了 `redis`、`Pillow`、`scikit-learn` 等模块
- 但 `requirements.txt` 中未列出这些依赖

**问题原因**：
- 开发环境中可能通过其他方式安装了这些依赖
- 依赖管理不完整

**解决方案**：
1. 在 `requirements.txt` 中添加缺失的依赖：
   ```
   redis>=5.0.0
   Pillow>=10.0.0
   scikit-learn>=1.3.0
   transformers>=4.35.0
   requests>=2.31.0
   ```

**预防措施**：
- 使用 `pip freeze` 导出完整依赖列表
- 定期检查依赖完整性

### 问题 4：Milvus 连接配置

**问题描述**：
- `.env` 中 `MILVUS_HOST=localhost` 在容器中无法连接 Milvus

**问题原因**：
- Docker 容器有独立的网络命名空间
- `localhost` 指向容器自身，而非宿主机或其他容器

**解决方案**：
1. 使用 Docker 服务名作为主机名：`MILVUS_HOST=milvus`
2. 在 `docker-compose.yml` 中配置网络：
   ```yaml
   networks:
     rag-network:
       driver: bridge
   ```

**预防措施**：
- 在 Docker 环境中使用服务名而非 localhost
- 使用 Docker Compose 的服务发现功能

### 问题 5：GPU 支持配置

**问题描述**：
- 容器中无法使用 GPU 进行模型推理
- `torch.cuda.is_available()` 返回 `False`

**问题原因**：
- Docker 默认不暴露 GPU 给容器
- 需要安装 NVIDIA Container Toolkit

**解决方案**：
1. 安装 NVIDIA Container Toolkit：
   ```bash
   distribution=$(. /etc/os-release;echo $ID$VERSION_ID)
   curl -s -L https://nvidia.github.io/libnvidia-container/gpgkey | sudo apt-key add -
   curl -s -L https://nvidia.github.io/libnvidia-container/$distribution/libnvidia-container.list | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
   sudo apt-get update
   sudo apt-get install -y nvidia-container-toolkit
   sudo systemctl restart docker
   ```

2. 在 `docker-compose.yml` 中配置 GPU：
   ```yaml
   deploy:
     resources:
       reservations:
         devices:
           - driver: nvidia
             count: 1
             capabilities: [gpu]
   ```

**预防措施**：
- 在部署文档中明确 GPU 要求
- 提供 CPU 备选方案

### 问题 6：前端无法访问后端 API

**问题描述**：
- 前端页面加载成功，但无法获取数据
- 浏览器控制台显示 API 请求失败

**问题原因**：
- Nginx 配置中 API 代理地址错误
- 前端请求路径与后端路由不匹配

**解决方案**：
1. 在 `nginx.conf` 中正确配置代理：
   ```nginx
   location /api/ {
       proxy_pass http://backend:8007;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
   }
   ```

2. 确保前端 API 路径正确：
   ```typescript
   const API_BASE = '/api';
   ```

**预防措施**：
- 使用环境变量配置 API 地址
- 在开发和生产环境使用相同的路径前缀

### 问题 7：数据持久化问题

**问题描述**：
- 容器重启后数据丢失
- Milvus 中的向量数据消失

**问题原因**：
- 未正确配置 Docker 卷
- 数据存储在容器内部而非持久化存储

**解决方案**：
1. 在 `docker-compose.yml` 中配置卷：
   ```yaml
   volumes:
     - ./data:/app/data
     - ./storage:/app/storage
     - ./logs:/app/logs
     - milvus_data:/var/lib/milvus
   ```

2. 使用命名卷而非绑定挂载：
   ```yaml
   volumes:
     milvus_data:
       driver: local
   ```

**预防措施**：
- 在部署文档中明确数据持久化要求
- 定期备份重要数据

---

### 问题 8：SSE（Server-Sent Events）连接中断

**问题描述**：
- 流式输出中断
- 文档上传进度无法实时更新

**问题原因**：
- Nginx 默认缓冲响应
- SSE 需要禁用缓冲

**解决方案**：
1. 在 `nginx.conf` 中禁用缓冲：
   ```nginx
   location /api/ {
       proxy_http_version 1.1;
       proxy_set_header Connection "";
       proxy_buffering off;
       proxy_cache off;
       proxy_read_timeout 300s;
   }
   ```

**预防措施**：
- 在 Nginx 配置中明确 SSE 支持
- 测试流式输出功能
