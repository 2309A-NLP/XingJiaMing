# 更新日志 - 工单4

## 2026-06-03 进度同步修复

### Bug 修复

**进度条一直显示 0%**
- 问题：前端进度条显示但一直为 0%，SSE 连接正常但数据不更新
- 原因：`api/progress.py`（BatchProcessor 使用）和 `api/queue_manager.py`（前端 SSE 订阅）是两套独立的进度系统，互不通信
- 修复：新增 `_sync_progress` 协程，每 1 秒将 `progress.py` 的详细进度同步到 `queue_manager`

**事件循环阻塞**
- 问题：`processor.process()` 是同步阻塞调用，卡死事件循环导致 SSE 推送失败
- 修复：改用 `asyncio.run_in_executor()` 放到线程池运行，事件循环保持畅通

**report.pages 字段不存在**
- 问题：`IngestReport` 使用 `total_pages` 字段，代码中误用 `report.pages` 导致完成时进度永远为 0
- 修复：改为 `report.total_pages`

## 2026-06-03 功能迭代

### 新增功能

**多文档共存**
- 支持同时加载多份 PDF 文档，查询时自动区分来源
- 上传新文档时追加到索引，不清除旧数据
- LLM 回答中标注信息来自哪份文档（如"根据《招股说明书2》..."）

**文档解析队列**
- 支持多文件同时上传，自动排队解析
- 实时显示解析进度（SSE 推送，每秒更新）
- 显示当前解析文件、进度百分比、页数、批次、预计剩余时间
- 待解析文件队列显示

**断点续传**
- 解析中断后重启，自动跳过已完成的批次
- 状态文件保存在 `storage/` 目录

**暂停/继续解析**
- 支持暂停当前解析任务
- 暂停后可继续，从当前位置恢复

**多模态图片解析**
- 集成 mimo-v2.5 多模态模型
- OCR 文字少于 200 字的页面自动触发图片语义解析
- 解析结果追加到文档内容

**分块缓存**
- 分块结果缓存到 `storage/chunks_cache.pkl`
- 后续启动直接读缓存，跳过分块（省几秒启动时间）
- 上传新文档时自动更新缓存

**来源过滤**
- 向量存储支持按 `source_file` 过滤查询
- 新增 `query_by_source()` 方法判断文档是否已入库

### 性能优化

**响应时间优化**
- 砍掉 Query Understanding（省 3 秒）— 改用纯规则判断意图
- 跳过 Rerank（省 0.3 秒）— RRF 融合已足够准确
- 问候语不调 LLM（秒回）— 直接返回固定回答
- BM25 权重提升到 1.5x — 关键词匹配更准

**启动优化**
- 分块结果缓存，避免重复分块
- 已在 Milvus 中的文档跳过编码
- 端口清理等待时间增加到 20 秒

### Bug 修复

**chunk_id 冲突**
- 问题：多文档的 chunk_id 相同（都是 c0000, c0001...），Milvus 主键冲突导致数据覆盖
- 修复：chunk_id 加文档名哈希前缀（如 `a3b1_c0000`）

**前端不显示内容**
- 问题：API 返回正确 JSON，但前端只显示响应时间
- 修复：后端 SSE 格式改为 `{"type": "token", "data": "xxx"}`，与前端期望一致

**.env 编码错误**
- 问题：PowerShell `Set-Content` 写入 GBK 编码，Python 读取 UTF-8 失败
- 修复：用 `[System.IO.File]::WriteAllText()` 强制 UTF-8

**sentence-transformers 兼容性**
- 问题：3.3.1 版本与 PyTorch 2.5 的 meta tensor 不兼容
- 修复：降级到 2.7.0

**端口清理超时**
- 问题：CUDA 进程释放显存慢，5 秒等待不够
- 修复：start.bat 先杀所有 Python 进程，循环检测端口释放

**检索精度低**
- 问题：向量检索返回泛泛结果，BM25 关键词匹配被稀释
- 修复：BM25 权重 1.5x，增大内部检索候选数（top_k * 3）

**排序错误**
- 问题：用 `score` 排序而不是 `rrf_score`，RRF 融合白做
- 修复：改为按 `rrf_score` 降序排列
