## 三、核心优化（相比工单1）

### 3.1 检索优化

| 优化项 | 工单1 | 工单2 |
|--------|-------|-------|
| BM25 分词 | 字符级 | jieba 分词 + 停用词过滤 |
| 多路融合 | hit_count 排序 | RRF 倒数排名融合（k=60） |
| Rerank | 关闭 | bge-reranker-base (GPU) + 智能跳过 |
| 分块策略 | 固定字符切割 | 表格保护 + 句子边界分块 + 重叠 |

**智能 Rerank 策略**：top-1 双路命中（hit_count=2）且 top-k 单路命中时跳过 Rerank，节省 1-2 秒。

### 3.2 生成优化

Prompt 加了 5 条硬规则：
1. 只用参考资料里的信息回答
2. 优先使用原文措辞
3. 覆盖所有相关要点
4. 数据必须注明时间段
5. 不添加原文没有的定性判断

temperature 从 0.3 降到 0.1，回答更贴合原文。

### 3.3 性能优化

| 环节 | 优化前 | 优化后 |
|------|--------|--------|
| Embedding 设备 | CPU | GPU (CUDA)，速度提升 5x |
| Rerank 设备 | CPU | GPU (CUDA)，<0.5s |
| Query 理解 | 每次都跑 | 简单问题跳过（省 2-3s） |
| 执行方式 | 串行 | Query 理解 + Embedding 并行 |
| 查询缓存 | 无 | 内存缓存 TTL 300s，最多 200 条 |
| 检索候选数 | top_k*2=10 | top_k+3=8 |
| Rerank 候选 | 全部 | 智能跳过 / top 8 |
| LLM 上下文 | 5 个 parent 块 | 3 个 parent 块 |
| 首 token 响应 | ~5s | ~3s（专业问题）/ ~1s（问候语） |

### 3.4 详细耗时分析

日志中记录每个步骤的精确耗时：

```
检索完成: 5 结果, 耗时 2.16s [校验=0.00s, 初始化=0.00s, 检索=2.16s]
首个 token 生成: LLM 首 token 耗时 0.72s, 总耗时 2.88s
```

典型耗时分布（专业问题）：
- 翻译（英文查询）：~1s
- Embedding + 检索 + Rerank：~1.5s
- LLM 首 token：~0.8s
- **总计：~3s**

### 3.5 简单问题判断

`_is_simple_query()` 函数判断问题复杂度，简单问题跳过 Query Understanding：

- 中文 ≤20 字符
- 包含"是什么/有多少/谁是/在哪里"等模式且 ≤30 字符
- 英文包含"who is/what is/how many"等模式且 ≤60 字符

英文查询先翻译为中文再判断，避免英文长度误判。

### 3.6 查询缓存

```python
_query_cache = {}
_ttl = 300     # 5 分钟过期
_max_size = 200  # 最多 200 条
```

缓存命中时直接返回结果，不经过检索和 LLM，响应时间 ~0.01s。

## 七、启动与部署

### 一键启动
双击 `start.bat`，自动完成后端启动（含端口清理）和前端启动。

### 手动启动
```bash
# 后端（必须使用项目 .venv）
.venv\Scripts\python.exe run.py

# 前端
cd frontend && npm run dev
```

### 端口自动清理
`run.py` 启动时自动检测 8002 端口占用，若被占用则通过 `taskkill` 清理对应进程，等待端口释放后启动。

### 依赖隔离
项目使用独立的 `.venv` 虚拟环境，不依赖其他项目的 site-packages。
