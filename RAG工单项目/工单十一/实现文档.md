## 2. 第一步：文档分段（01_chunk.py）

### 2.1 目的

将 9 份长篇金融年报切成适合 Embedding 模型处理的小段落。

**为什么要分段？**
- Embedding 模型最大输入 512 token（约 250 个中文字）
- 检索是按"段落"匹配的，不是整篇文档
- 段落太长会丢失细节，太短会丢失上下文

### 2.2 分段策略

| 参数 | 值 | 说明 |
|------|-----|------|
| CHUNK_SIZE | 250 字 | 每段目标字数 |
| OVERLAP | 50 字 | 相邻段落重叠字数 |
| MIN_CHUNK_LEN | 50 字 | 太短的段落丢弃 |

### 2.3 分段流程

```
原始文档.md
    ↓
Step 1: 清理文本
    - 去掉 "## 第 X 页" 标记
    - 去掉连续空行
    - 去掉行首尾空格
    ↓
Step 2: 去掉标题行（第一行通常是文件名重复）
    ↓
Step 3: 按段落切分（以双换行 \n\n 为分隔符）
    ↓
Step 4: 合并短段落
    - 如果 buffer + 当前段落 < 250字，就合并
    - 如果 buffer 已经够大，存起来，开始新 buffer
    ↓
Step 5: 对超长段落进一步切分
    - 超过 500 字的段落，按 250 字切分
    - 尝试在标点符号处断开（。！？；，）
    - 相邻切分有 50 字重叠
    ↓
Step 6: 生成 chunk 对象
    - chunk_id: "文档名_chunk_0001"
    - text: 段落文本
    - source: 来源文档名
    - char_count: 字数
```

## 3. 第二步：LLM生成问答对（02_generate.py）

### 3.1 目的

用 LLM（mimo-v2.5-pro）从文档段落中生成用户可能会问的问题，构建训练数据。

**为什么不直接用文档原文当 query？**
- 用户不会用书面语提问（"请介绍一下MLF操作" vs "MLF是啥？"）
- LLM 生成的问题更口语化、更多样化

### 3.2 配置参数

| 参数 | 值 | 说明 |
|------|-----|------|
| SAMPLE_SIZE | 400 | 从 16,266 段中采样 400 段 |
| QUESTIONS_PER_CHUNK | 3 | 每段生成 3 个问题 |
| TEMPERATURE | 0.8 | 生成多样性（0-1，越高越多样） |
| LLM Model | mimo-v2.5-pro | 小米 MiMo 推理模型 |
| API Endpoint | https://token-plan-cn.xiaomimimo.com/v1/chat/completions | 直连 API |

### 3.3 采样策略

```
16,266 段落
    ↓
按文档分组（9 个文档）
    ↓
每个文档采样 44-46 段（均匀分布）
    ↓
过滤掉表格/列表类型的段落（不适合生成问题）
    ↓
过滤掉太短的段落（< 100 字）
    ↓
最终采样 400 段
```

**为什么按文档均匀采样？** 确保每个文档都有代表，不会因为某个文档特别长而占主导。

### 3.4 LLM Prompt 设计

```
你是一个金融领域的普通用户，正在使用一个金融问答系统。
请根据以下金融文档段落，生成3个用户可能会问的问题。

要求：
1. 问题要口语化，像真人在问（不要照抄文档原话）
2. 问题要多样化：有的直接问，有的换个角度问，有的问细节
3. 问题必须能从这个段落中找到答案
4. 不要生成和段落内容无关的问题

文档段落：
"""
{chunk_text}
"""

请直接输出问题列表，每行一个，不要编号，不要其他内容：
```

**Prompt 设计要点：**
- 角色设定为"普通用户"，让 LLM 生成口语化问题
- 要求"多样化"，避免生成 3 个几乎一样的问题
- 要求"能从段落中找到答案"，确保问题和段落的关联性

## 4. 第三步：挖掘困难负例（03_mine_neg.py）

### 4.1 目的

为训练集中的每个样本找到"困难负例"——看起来和问题相关、但实际不回答这个问题的段落。

### 4.2 困难负例 vs 随机负例

```
问题："MLF是什么意思？"
正例："MLF（中期借贷便利）是央行于2014年9月创设的..."

随机负例："2024年GDP增速为5.2%..."
→ 太容易区分，模型学不到东西

困难负例："SLF（常备借贷便利）是央行的另一个流动性工具..."
→ 看起来相关但不回答问题，模型需要仔细分辨
```

### 4.3 挖掘流程

```
Step 1: 加载原始 bge-base-zh-v1.5 模型
    ↓
Step 2: 编码所有 16,266 个段落 → 向量（GPU，约2分钟）
    ↓
Step 3: 对每个训练样本的 query：
    - 编码 query → 向量
    - 计算 query 向量与所有段落向量的余弦相似度
    - 按相似度降序排列
    - 取 Top 20 个结果
    - 排除正例本身
    - 第一个不是正例的 = 困难负例
    ↓
Step 4: 组装三元组 (anchor, positive, negative)
    ↓
Step 5: 保存到 train_final.jsonl
```

### 4.4 余弦相似度计算

```python
def cosine_similarity(a, b):
    # a: (1, 768) query向量
    # b: (16266, 768) 所有段落向量
    a_norm = a / np.linalg.norm(a, axis=1, keepdims=True)
    b_norm = b / np.linalg.norm(b, axis=1, keepdims=True)
    return np.dot(a_norm, b_norm.T)  # (1, 16266)
```

## 5. 第四步：微调前评估（04_evaluate.py）

### 5.1 目的

用原始模型（微调前）在测试集上评估，建立 baseline 基准。

### 5.2 评估流程

```
Step 1: 加载原始模型 bge-base-zh-v1.5
    ↓
Step 2: 编码所有 16,266 个段落 → 向量库（约2分钟）
    ↓
Step 3: 对测试集的每条 query：
    - 编码 query → 向量
    - 计算与所有段落的余弦相似度
    - 取 Top 10 结果
    - 和正确答案对比，计算指标
    ↓
Step 4: 汇总所有 query 的指标，取平均值
```

### 5.3 评估指标

| 指标 | 计算方式 | 含义 |
|------|---------|------|
| **Recall@10** | 前10个结果中命中的正确答案数 / 总正确答案数 | 检索命中率 |
| **MRR** | 1 / 第一个正确结果的排名 | 第一个正确答案排第几 |
| **NDCG@10** | DCG / IDCG（考虑排名位置的增益） | 排名质量 |
| **Precision@10** | 前10个结果中正确的数量 / 10 | 精确率 |

### 5.4 NDCG 详细计算

```python
# DCG (Discounted Cumulative Gain)
dcg = 0
for rank, chunk_id in enumerate(top_10_results, 1):
    if chunk_id in relevant_ids:
        dcg += 1.0 / log2(rank + 1)  # 排名越靠前，增益越大

# IDCG (Ideal DCG) - 理想情况下的最大 DCG
ideal_dcg = sum(1.0 / log2(i + 2) for i in range(min(len(relevant_ids), 10)))

# NDCG
ndcg = dcg / ideal_dcg
```

## 6. 第五步：模型微调训练（05_train.py）

### 6.1 目的

用训练数据（1,220 条）微调 bge-base-zh-v1.5 模型。

### 6.2 训练参数

| 参数 | 值 | 说明 |
|------|-----|------|
| EPOCHS | 1 | 训练轮数（1轮防过拟合） |
| BATCH_SIZE | 16 | 每批次样本数 |
| LEARNING_RATE | 5e-6 | 学习率（低学习率防坍塌） |
| WARMUP_RATIO | 0.1 | 前10%步数预热 |
| MAX_SEQ_LENGTH | 128 | 最大 token 数 |
| 损失函数 | MultipleNegativesRankingLoss | 业界标准 |

### 6.3 训练流程

```
Step 1: 加载原始模型 bge-base-zh-v1.5
    ↓
Step 2: 加载训练数据 train_final.jsonl（1,220 条）
    ↓
Step 3: 构建训练样本
    - 每条样本 = InputExample(texts=[anchor, positive])
    - 负例由 MultipleNegativesRankingLoss 自动从 batch 内其他样本选取
    ↓
Step 4: 创建 DataLoader
    - shuffle=True（打乱顺序）
    - batch_size=16
    ↓
Step 5: 定义损失函数 MultipleNegativesRankingLoss
    - 原理：batch 内其他样本的 positive 自动作为当前样本的 negative
    - 优点：不需要显式提供负例，batch 越大负例越多
    ↓
Step 6: 计算训练步数
    - 总步数 = (1220 / 16) × 1 = 77 步
    - 预热步数 = 77 × 0.1 = 8 步
    ↓
Step 7: 开始训练
    - 每步：前向传播 → 计算 loss → 反向传播 → 更新参数
    - 前8步：学习率从0线性增加到 5e-6
    - 之后：学习率保持 5e-6
    ↓
Step 8: 保存模型到 model/bge-finetuned/
```

### 6.4 MultipleNegativesRankingLoss 原理

```
Batch 内有 16 个样本：
  样本1: (query1, positive1)
  样本2: (query2, positive2)
  ...
  样本16: (query16, positive16)

对于样本1：
  正例 = positive1
  负例 = positive2, positive3, ..., positive16（batch内其他样本的正例）

损失函数 = -log(exp(sim(query1, positive1)) / Σexp(sim(query1, positive_i)))

翻译：让 query1 和 positive1 的相似度尽可能高，和其他 15 个 positive 尽可能低
```
