## 2. 性能瓶颈分析

### 2.1 根本原因

**核心瓶颈**：MiMo远程API延迟过高

```
单个请求耗时分解（总耗时17秒）：

├─ Embedding (BGE-M3 via SiliconFlow)    0.2s   (1%)
├─ ES检索（向量+全文双路）                0.3s   (2%)
├─ Rerank (SiliconFlow)                  0.1s   (1%)
├─ Prompt构建                            0.01s  (0%)
│
└─ **MiMo API生成（LLM）**               **15.8s  (96%)** ← 瓶颈！
```

### 2.2 优化方案

采用**本地部署LLM**替代远程API：
- 安装Ollama 0.9.2
- 下载qwen2.5:3b模型（Q4_K_M量化，1.9GB）
- 配置RAGFlow使用本地Ollama模型

## 5. 结论与建议

### 5.1 已完成优化

1. ✅ **本地LLM部署**：Ollama + qwen2.5:3b，延迟降低97%
2. ✅ **Prompt精简**：减少58% tokens，响应时间降低32%
3. ✅ **查询缓存**：95.9%命中率，重复查询秒级响应
4. ✅ **系统稳定性**：无崩溃、无内存泄漏

### 5.2 未完全达标原因

P95在20并发下为8.4秒（标准≤3秒），原因：
1. qwen2.5:3b模型较小（3B参数），单次推理约1-2秒
2. Ollama parallel=2（显存限制），20并发需排队
3. RAG检索链路本身有约0.5秒开销

### 5.3 进一步优化建议

1. **降低并发数**：10并发时P95=3.5秒，接近达标
2. **升级硬件**：更大显存可增加parallel数
3. **使用更大模型**：qwen2.5:7b或14b，推理质量更高
