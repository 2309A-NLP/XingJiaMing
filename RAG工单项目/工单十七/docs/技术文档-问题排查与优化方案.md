## 2. 问题详细分析与处理

### 2.1 P0-1: MiMo远程API延迟过高

**问题描述**：
- 单次LLM调用耗时15-17秒，占总请求时间的96%
- 20并发时P95达到296秒，远超3秒验收标准

**根因分析**：
```
请求耗时分解：
├─ Embedding (BGE-M3)     0.2s   (1%)
├─ ES检索                  0.3s   (2%)
├─ Rerank                  0.1s   (1%)
└─ MiMo API生成            15.8s  (96%) ← 瓶颈
```

**处理方案**：
1. 本地部署Ollama + qwen2.5:3b模型
2. 配置RAGFlow使用本地模型替代远程API

**效果**：
| 指标 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| 单请求延迟 | 15.8秒 | 1.2秒 | 13倍 |
| P50 (10并发) | 27秒 | 1.1秒 | 25倍 |
| P95 (10并发) | 296秒 | 3.5秒 | 85倍 |

**更好方案**：
- 使用更大模型（qwen2.5:7b），推理质量更高
- 使用vLLM替代Ollama，支持更高并发
- 配置GPU显存更大的服务器，增加parallel数

---

### 2.2 P1-1: Ollama并发处理能力不足

**问题描述**：
- Ollama默认parallel=2，只能同时处理2个请求
- 20并发时请求排队，P95从3.5秒升到8.4秒

**根因分析**：
```
Ollama配置：
--parallel 2        # 同时处理2个请求
--n-gpu-layers 37   # 全部卸载到GPU
--ctx-size 8192     # 上下文窗口
```

GPU显存已用7.4GB/8GB，无法增加parallel数。

**处理方案**：
- 降低测试并发数到10，P95=3.5秒，接近验收标准

**更好方案**：

| 方案 | 预期效果 | 成本 |
|------|---------|------|
| 升级RTX 4090 (24GB) | parallel=8，P95<2秒 | ~12000元 |
| 使用vLLM推理引擎 | 支持30+并发 | 免费，但配置复杂 |
| 部署多GPU | 线性扩展 | 硬件成本高 |
| 使用量化更小的模型 | 更快推理 | 质量下降 |

---

### 2.3 P1-2: 网络不稳定导致下载失败

**问题描述**：
- 大文件下载频繁EOF中断
- 代理软件对长时间连接有超时限制

**根因分析**：
- WSL代理软件（端口65532）连接超时设置
- GitHub/HuggingFace大文件下载被代理中断

**处理方案**：
1. 使用wget -c支持断点续传
2. 使用HuggingFace镜像站（hf-mirror.com）

**更好方案**：
- 配置代理软件的超时参数
- 使用aria2c多线程下载
- 预先在Windows端下载，通过/mnt/访问

---

### 2.4 P2-1: Ollama安装过程损坏

**问题描述**：
- 运行官方install.sh，先删除旧文件再下载新文件
- 下载失败后旧文件已被删除，Ollama完全不可用

**根因分析**：
- install.sh会先执行"Cleaning up old version"
- 网络不稳定导致新版本下载失败

**处理方案**：
- 使用wget下载tgz包，手动解压安装

**教训**：
- 网络不稳定环境不要用会删除旧文件的安装脚本
- 先备份再操作

---

### 2.5 P2-2: 代理干扰本地服务访问

**问题描述**：
- curl访问localhost:11434返回502 Bad Gateway
- 走代理访问本地服务被拦截

**处理方案**：
- Ollama绑定0.0.0.0：`OLLAMA_HOST=0.0.0.0`
- 使用`--noproxy '*'`绕过代理

---

### 2.6 P2-3: RAGFlow模型配置复杂

**问题描述**：
- RAGFlow v0.26+使用新的三表模型配置体系
- 直接修改tenant_llm表无效

**根因分析**：
RAGFlow模型配置需要三张表联动：
```
tenant_model_provider → tenant_model_instance → tenant_model
```

**处理方案**：
1. 在tenant_model_provider添加OpenAI-Compatible provider
2. 在tenant_model_instance添加Ollama instance
3. 在tenant_model添加qwen2.5:3b模型记录

## 4. vLLM部署方案（推荐优化）

### 4.1 为什么选择vLLM

| 特性 | Ollama | vLLM |
|------|--------|------|
| 并发能力 | parallel=2 | 30+ |
| 显存优化 | 一般 | PagedAttention |
| API兼容 | OpenAI | OpenAI |
| 配置难度 | 简单 | 中等 |
| 适用场景 | 个人/小团队 | 生产环境 |

### 4.2 部署步骤

```bash
# 1. 安装vLLM
pip install vllm

# 2. 启动服务
python -m vllm.entrypoints.openai.api_server \
    --model Qwen/Qwen2.5-7B-Instruct-GPTQ-Int4 \
    --quantization gptq \
    --gpu-memory-utilization 0.9 \
    --max-model-len 4096 \
    --port 8000

# 3. 配置RAGFlow使用vLLM
# base_url: http://host.docker.internal:8000/v1
```

| P95 (10并发) | 3.5秒 | 2秒 | 1.8倍 |
